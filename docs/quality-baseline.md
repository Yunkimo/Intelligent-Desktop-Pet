# 提醒质量口径（B2 / A4 本轮实施）

原 #6 同时写“30 秒扫描”“创建到期时间 now+60 秒”“60 秒内收到”，计时起点有歧义。
2026-10-12 用户在知悉验收问题和解决建议后，授权本轮统一完成 B2 与 A4 修改。
本轮采用“从计划到期计时，联调扫描 1 秒，到期后 5 秒内显示”的口径；
不再使用“创建后 60 秒内显示一个 60 秒后才到期的提醒”作为可实现的验收条件。
此处记录用户授权的实施决定，不冒充其他成员独立评审或覆盖教师原始要求。

| 项目 | 当前测量或目标 | 验证状态 |
|---|---|---|
| 基本正确性 | 不能早于计划到期触发；正确通知并写回状态 | 固定时钟与真实网络测试 |
| 计时起点 | 计划 remind_at 对应的 UTC 时刻 | 脚本明确记录 |
| B2 观测终点 | WebSocket 客户端收到事件时刻 | 当前实测 |
| 桌宠验收终点 | 桌宠气泡实际绘制，另用截图核对内容 | 必须使用真实 WS、REST、窗口链路 |
| 联调配置 | 扫描间隔 1 秒，目标到期至显示 ≤5 秒 | 30 条提醒全部限时显示，无重复通知；voice 另验 |
| 默认配置 | 30 秒扫描，分别报告实际延迟 | 不套用 ≤5 秒结论 |
| 样本 | 每种配置至少 30 次，报告全部失败/超时/重复 | 原始 JSON 随报告提交 |
| 分布 | 成功率、p50/p95/max，nearest-rank 分位数 | 按成功收包样本计算，另列失败分母 |
| 时间误差 | 当前服务与客户端同机；报告墙钟/单调钟增量差 | 无跨机器误差结论 |

默认组脚本用 35 秒作为本次观测失败阈值，不代表团队已承诺该 SLA。
改动阈值必须说明理由与前后数据；不得以无限等待“最终收到”代替限时验证。

复现使用 `backend/.env.integration.example`；默认兼容配置仍为 30 秒，不能用它证明五秒目标。
等价单条条件：`remind_at=now+60s`，应在到期后 5 秒内显示，即创建后约 60–65 秒。
恢复用例允许网络重复投递，但同一窗口内同 event_id 只通知一次。小程序及语音不能用气泡测试代替。
