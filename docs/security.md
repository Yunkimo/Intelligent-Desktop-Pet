# 配置、隐私与安全边界

依据当前源码与[C4报告](c4-verification.md)整理，不宣称整体安全验收通过。正式HTTPS/WSS不纳入本轮C4，不会消除HTTP明文与共享凭据风险。

## 1. 配置和凭据

| 位置 | 用途 | 边界 |
|---|---|---|
| 根目录 `.env` | 桌宠LLM、余额查询、后端入口与API_TOKEN | 本机忽略文件 |
| `backend/.env` | 后端鉴权、视觉Key、微信服务端凭据、数据库及调度 | 限制文件权限，修改后按部署方式重启 |
| `miniprogram/config.js` | 客户端入口和演示API Key | 被Git忽略，但打包客户端不提供秘密存储 |
| `config.json` | 外观及非敏感偏好 | 跟踪文件，禁止放真实Key |

只提供示例，复制前保留已有配置。Key不放截图、命令参数、公开日志或对话；桌宠LLM Key、后端视觉Key与业务API_TOKEN用途不同。全局或进程环境可能覆盖.env，排查时只显示状态，不打印Key。

## 2. 当前网络和授权

- REST通过X-API-Key鉴权；WS在URL query携带token并在握手前校验。共享Key可访问演示业务，不是多租户授权。
- 微信订阅接口使用服务端code交换后签发的Bearer会话，按B3实现保留摘要、有效期、AppID/用户绑定；openid不是认证凭据。见[契约](api-contract.md)。
- 当前公网IP/HTTP/WS和开发调试豁免不加密Key及业务内容，不能从“有鉴权”推导传输安全。
- 用户在本轮排查中将8080入方向来源放行为所有IPv4。这扩大网络暴露范围，不授予业务权限，也不记为安全验收成功。
- HTTPS/WSS模板与实际证书验证分别记账，不关闭TLS校验来伪造正式通过。C5不改服务器、安全组或微信平台配置。

## 3. 数据和外部服务

- faster-whisper本机转写录音，首次模型下载需要网络；应记录具体模型ID、修订与许可。
- LLM收到当前消息及应用提供的对话上下文；历史文件在本地不表示其内容从不发送给模型。
- 在线edge-tts向服务发送待播报文本；Windows本地语音兜底是另一条路径，不保证每次离线。
- 所选课表图片会发送到后端配置的视觉服务；parse-image不落库，用户确认后bulk接口写入课程。
- 微信服务接收code、服务端凭据、身份及模板字段。AppSecret、session_key和access_token不进入小程序。
- B4将受约束的城市/关键词发送到固定查询服务，不发送整个数据库。模块实现与测试见[契约](api-contract.md)和[测试说明](testing.md)。

## 4. 输入、日志和错误

用户文本作为消息/工具输入，不拼接为Shell命令；SQL参数绑定。工具可造成真实业务写入，提示注入和共享Key边界仍需管理。外部返回按数据展示，不当作指令或可信HTML执行。

后端日志过滤敏感查询参数，Nginx访问日志不记录query。原始Nginx错误日志可能带WS token，当前模板避免保留该类原始日志，结合受控日志和upstream状态诊断；这是诊断与脱敏之间的取舍。网络超时、401/403、502/504和413分开处理，网络错误不能冒充鉴权拒绝成功。

CI只归档测试生成的JUnit、覆盖率、审计JSON和检查输出，不归档.env、config.js、数据库、对话历史、真实课表或含token的URL。

## 5. 数据、备份和进程

服务器单worker、单调度实例，不开开发热重载；后端回环监听，由Nginx提供入口和Upgrade。运行用户、UMask与持久化目录见[部署手册](deploy.md)。旧run.py是热重载开发入口，与部署启动器不同。

备份使用SQLite快照并做完整性检查，恢复先写新副本。实际替换业务库和代码需另行切换，不能把隔离演练当作生产发布。演示重置受路径和停服确认保护。备份不等于加密或多用户隔离，仍需限制文件权限与保留周期。

## 6. 供应链、许可和已知限制

桌宠requirements为版本下限，解析结果可变；后端有平台条件锁文件，小程序开发工具有npm锁文件。CI复用pip-audit，某次无已知漏洞不等于没有漏洞。自有代码MIT声明不覆盖第三方库、Qt、模型或素材，见[第三方说明](../THIRD_PARTY_NOTICES.md)。

| 限制 | 当前事实 | 核对归属 |
|---|---|---|
| 多用户数据授权 | 当前共享Key与全库业务接口 | A/B/C共同设计，文档不代替实现 |
| HTTP/WS公网访问 | 明文，所有IPv4可尝试8080 | 部署使用者按环境决定 |
| 正式域名/证书/发布 | 当前IP结果不能验证 | 不计作本轮已通过项 |
| PyQt6、Qt和媒体二进制 | 许可随实际分发物核对 | 维护者与打包者 |
| Rice.png、tray.webp | 有仓库引入历史，上游来源/许可未找到 | 素材提供者/成员A补充 |
| 模型及服务条款 | 库许可不替代模型/服务使用条件 | 使用者记录真实配置 |

C5记录事实与未知项，C4提供已有部署证据；不重复计分、不代写其他成员完成结论。
