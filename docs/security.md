# 信息安全设计

## 1. 密钥管理

- API 密钥只存于 `.env`，该文件已加入 `.gitignore`，**不进入版本库**。
- 仓库内仅提供 `.env.example` 占位模板。
- 应用密钥经桌面 `Settings` 或后端 `config` 从环境变量读取；测试中仅使用独立假值。

## 2. 配置与逻辑解耦

- 敏感配置（`.env`）与非敏感配置（`config.json`）分离。
- 密钥、base_url、模型名均通过配置注入，避免硬编码泄漏与误提交。

## 3. 隐私与数据

- **语音识别本地执行**（faster-whisper 本地推理），录音与转写不离开本机。
- 对话历史仅存于本地 `data/history.json`（已 gitignore），不自动上传。
- 网络请求包括配置的模型与语音服务、桌面/手机与后端的 REST/WS 通信、天气和搜索公共服务，以及显式启用后的微信登录、token 与订阅发送。B4 把用户提供的城市/关键词发送给相应上游且不传后端 API Key；微信接收 openid 和所配置的提醒模板字段，不上传整个数据库。

## 4. 输入处理

- 用户文本与语音转写文本仅作为 LLM 消息内容传递，**不被当作代码执行**。
- 对 LLM 返回内容仅做展示与语音合成，不执行、不拼接进任何命令。

## 5. 依赖与供应链

- 依赖声明于 `requirements.txt`（含版本下限），可复现安装。
- 全部采用 PyPI 官方发布、广泛使用的库（PyQt6/openai/edge-tts/faster-whisper 等）。
- 项目采用 MIT 许可证。

## 6. 已知风险与改进方向

| 风险 | 说明 | 建议 |
|---|---|---|
| 提示注入 | LLM 可能被恶意输入诱导偏离人设 | 对人设指令加约束，限制输出长度与行为 |
| 语音权限 | 录音需麦克风授权 | 运行时明确提示，仅在使用时开启 |
| 第三方 API 依赖 | DeepSeek/edge-tts 可用性 | 通过 `ChatProvider` 策略可快速切换降级 |

## 7. B3 微信身份与推送

- API Key 是受信任演示环境的管理凭证，现有 CRUD 仍可访问全局数据。微信 Bearer 会话只保护订阅归属，不构成全应用多租户授权；不能把共享管理 Key 发布到公开小程序。
- code 在服务端交换身份，openid 不作凭证；session_key 丢弃，本地会话仅持久化 SHA-256 摘要，有效期受限，重新登录撤销旧会话。身份绑定 AppID，防止更换账号后复用旧会话。
- 不接受订阅请求中的任意 openid，按数据库归属选择收件人；SQL 参数化，登录响应禁止缓存，接口错误不返回上游正文。
- 微信主机固定为 `api.weixin.qq.com`，启用 TLS 验证，不跟随重定向；httpx 日志过滤 URL 查询参数，避免 code、AppSecret 和 access_token 泄露。服务运行环境和代理配置仍须受信任。
- 模板、超时、会话有效期集中配置；用户拒绝不发送。网络结果不明时持久化 uncertain，禁止自动重发；并发领取与幂等登记阻止重复消费。
- 公网部署还需 HTTPS、限流、用户级 CRUD 授权、数据库文件权限与隐私数据清理策略。当前没有声称完成这些部署能力。

实现边界、错误分类及恢复方式见 [B3 说明](b3-wechat.md)，安全用例见 [测试报告](b3-test-report.md)。B3 沿用已锁定的 httpx、FastAPI 等依赖，未新增第三方运行依赖；本次 `pip-audit -r backend/requirements.txt` 未发现已知漏洞。

## 8. B4 只读联网查询边界

天气/搜索接口沿用 X-API-Key。目标 HTTPS 主机固定、禁止跟随重定向，城市不能传 URL/IP/特殊路径，搜索关键词只作为参数编码。结果链接不被后端抓取。TLS 校验、总超时、并发上限和压缩前后大小上限同时启用；验证码、压缩损坏、畸形响应和超时均返回明确脱敏错误，不能伪装成正常摘要。

查询结果不持久化，响应为 JSON 纯文本字段；客户端必须将其作为不可信引用展示，不能用 innerHTML 或把内容当作模型系统指令。httpx/Uvicorn 查询参数脱敏，wttr URL 路径仍包含城市名；部署者需管理代理及访问日志。共享 API Key 不构成多租户授权，公网仍需 TLS、网关限流和访问控制。详见 [B4 说明](b4-web-query.md) 与 [用例](b4-test-report.md)。
