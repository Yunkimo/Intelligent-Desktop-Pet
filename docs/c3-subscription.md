## 实现与接口

修复时间字符串差异导致重复事件、所有 409 被误当成功、日程改期未失效旧提醒、本地 done 掩盖服务器状态、UTC 截取错时/漏列、phone 渠道承诺不符和并发创建问题。新增有身份校验的消息详情页，清理重复 README，并将 C3 检查接入 CI 配置。

以下微信接口均需要 X-API-Key 和 Bearer 会话；新增接口从会话获取用户，不接受客户端指定 user_id/openid。

| 接口 | 请求与返回 | 约束 |
|---|---|---|
| POST /api/wechat/reminders | `{ "task_id": 1 }`；200 返回提醒及 event_id | BEGIN IMMEDIATE 事务内读取最新日程并创建/复用本人 phone 提醒；重复请求和创建后丢响应返回同一资源 |
| GET /api/wechat/reminders | 本人 phone 提醒及当前 event_id、status | 页面刷新用；status=null 表示当前事件未登记，不以历史 sent 冒充成功 |
| GET /api/wechat/reminders/{id} | `{ "reminder": {...}, "task": {...} }` | 最新日程；不存在或非本人 404；无有效会话 401 |
| POST /api/wechat/subscribe | 原字段加可选 event_id；C3 必传 | 事件已变化返回 409 reminder_event_changed；旧客户端省略时保持原契约 |
| GET /api/wechat/subscriptions/{id} | 原历史记录增加 event_id | 按当前事件匹配；409 仍需查询实际状态 |

创建接口的 409：task_reminder_unavailable 表示任务不存在/无提醒时间；duplicate_task_reminders 表示历史有多条本人 phone 提醒，需核查，不自动删除。去重保证使用新入口的请求；共享管理 CRUD 仍可显式创建独立提醒，不是全系统唯一约束。

日程实际改期同时更新关联提醒并使旧 pending/retry 授权失效；清除时间和 DELETE 删除关联提醒及订阅。任一步失败整体回滚。同一时刻的格式变化不重新安排。提醒 PUT 保留既有“实际内容修改产生新事件”和“显式 done=false 重新安排”的语义；C3 不用这些操作恢复网络请求。

微信消息 page 为 `pages/reminder/reminder?reminder_id=<整数>`，不带凭据。发送请求已经出站时，改期/删除无法保证撤回；详情页始终重读最新资源。phone 不广播到期 WS 事件，页面状态通过恢复、重连和手动刷新更新。

全局 CRUD 仍使用共享管理 Key，是受控课程演示模型；本次只加强微信会话范围内的创建/查询，不宣称全系统用户隔离。新后端和客户端需一起部署；接口与原生跳转待 B/C 人工评审。

## 验证入口与结果

在仓库根目录运行 [小程序 README](../miniprogram/README.md) 的命令；断言失败返回非零退出码。环境 Windows 11、Python 3.13、Node 22.23.3。测试对象为本次修复工作树，提交后可用 `git rev-parse HEAD` 记录版本再复验。

| 层次 | 本轮结果 | 范围 |
|---|---|---|
| 客户端逻辑 | 13 项通过 | 同步授权、取消/拒绝/配置/登录失败、并发、409、持久恢复、改期、401/账号变化、不确定状态、时区；区分本次拒绝与旧登记 |
| 真实 HTTP | 10 组通过 | 实际 C3 JS/页面、FastAPI/SQLite、会话、调度；丢响应、并发、改期、WS 阳性对照、跳转目标与详情页 |
| 后端全量 | 251 项通过 | 既有 B2/B3/B4 与新增 C3 事务、并发、身份、事件、回滚回归；存在一条既有 Starlette 测试客户端弃用提示 |
| CI | 已新增 miniprogram-c3 job，尚未推送运行 | lint/format、逻辑与真实 HTTP；不能借其他 job 的绿色结果代替 |
| 微信真机 | 本轮未执行 | 模拟平台调用不算手机实收 |

HTTP 丢响应在服务端成功提交后注入，模块重载验证恢复；另有提交前失败和账号变化的逻辑回归。后端以 16 个并发调用验证创建事务。测试使用临时数据库与凭据，不覆盖 config.js，只模拟外部微信。

客户端与集成原始输出保存于 [evidence/c3](evidence/c3/verification.txt)。新开发工具 ESLint 10.13.0、Prettier 3.9.10 均为 MIT，版本及传递依赖由 package-lock.json 锁定，npm audit 本轮未发现已知漏洞；不增加业务运行依赖。Node 需使用 22.13+（本轮 22.23.3）。

修正过的失败：首轮实现误改显式 done=false 和标题变化的既有语义，已有回归发现后恢复；WS 夹具初用 resource_id，按实际信封 data.id 修正。夹具错误未计为产品缺陷。
