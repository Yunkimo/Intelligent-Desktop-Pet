## 3. 尚未执行的人工验收（待成员 C 在开发者工具与手机上完成）

1. 用 `tests_fixtures/b7/schedule.png`（或成员 C 自己的复杂课表截图）走「识」流程：
   - 选图后先出现图片预览；
   - 上传阶段显示「已等待 N 秒（最长 70 秒）」且可点「取消识别」；
   - 识别完成后出现草稿列表与警告；没有具体时间的课程已按标准节次自动预填（第1行→08:00-09:40 等），时间直接可见、可点「编辑」修改；
   - 点「配置节次时间」可看到预填值并按实际作息统一调整 → 应用映射；
   - 无节次标签的条目标「缺时间」，点「编辑」手填；确认前点「确认导入」会被提示补全且数据库不变；
   - 全部补全后确认导入 → 课表刷新，当前周不变。
2. 取消路径：上传中（模型慢时）点「取消识别」→ 立即结束等待、无转圈。
3. 超时路径：把 `config.js` 的 `parseTimeoutMs` 临时改小（如 8000）观察 8 秒后「识别超时（已等待 70 秒）」提示与实际等待时间一致，随后改回 70000。
4. 连点：识别进行中再点「识」不重复进入流程。
5. 真机预览同第 1、2 步（记录图片规格、等待耗时与识别结果条数）。

- 客户端等待上限默认 70 秒（`config.parseTimeoutMs`），对应 B7 服务端 60 秒预算；取消不宣称上游计算与费用已撤销。
- 上传前压缩参数调整为质量 80 / 宽 1920，避免压糊课表文字；原 10MB/1600 万像素限制由后端兜底（413）。
- 图中无具体时间时按标准节次时间预填（成员 C 指定的作息约定），预填值在草稿中可见可改、确认前不落库，不静默套用；超标准表（第 6 行起）或无节次标签的条目仍需手填。
- 确认前识别与草稿展示均不写数据库；批量导入仍每批仅发一次兼容的 course.created。
