- `tests/course-import-logic.test.js`：12 项，覆盖

  - 节次映射：只收集缺时间且带节次标签的条目、映射填充、无标签或非法映射不静默套用；
  - 批量保存结果核对：created 按序对应、skipped 按 index 标注原因、失败项单独筛出重试；
  - 响应不明先核对列表（同名同时段视为已存在，其余标「待确认」），核对失败也不自动重放；
  - uploadWithTask：abort 后 done 以 cancelled 拒绝、迟到成功回调不再结算、超时 errMsg 映射 timeout 标记、504 detail.code=parse_timeout 可读。

## 2. 真实后端联调（契约层）

命令：`python scripts/check_c7_integration.py`（B7 已合入 develop；真实后端 + 临时 SQLite，无视觉 Key）。

结果 5 项全部通过（完整输出见 [real-backend-integration.txt](real-backend-integration.txt)）：

## 3. 尚未执行的人工验收（待成员 C 在开发者工具与手机上完成）

1. 用 `tests_fixtures/b7/schedule.png`（或成员 C 自己的复杂课表截图）走「识」流程：
   - 选图后先出现图片预览；
   - 上传阶段显示「已等待 N 秒（最长 70 秒）」且可点「取消识别」；
   - 识别完成后出现草稿列表与警告，缺时间的课程标「缺时间」；
   - 点「配置节次时间」按实际作息填各节次时间（如 1-2 → 08:00-09:40）→ 应用映射；
   - 其余缺项点「编辑」补全（周次、星期）；确认前点「确认导入」会被提示补全且数据库不变；
   - 全部补全后确认导入 → 课表刷新，当前周不变。
2. 取消路径：上传中（模型慢时）点「取消识别」→ 立即结束等待、无转圈。
3. 超时路径：把 `config.js` 的 `parseTimeoutMs` 临时改小（如 8000）观察 8 秒后「识别超时（已等待 70 秒）」提示与实际等待时间一致，随后改回 70000。
4. 连点：识别进行中再点「识」不重复进入流程。
5. 真机预览同第 1、2 步（记录图片规格、等待耗时与识别结果条数）。

## 4. 边界与说明

- 客户端等待上限默认 70 秒（`config.parseTimeoutMs`），对应 B7 服务端 60 秒预算；取消不宣称上游计算与费用已撤销。
- 上传前压缩参数调整为质量 80 / 宽 1920，避免压糊课表文字；原 10MB/1600 万像素限制由后端兜底（413）。
- 图中无具体时间时不猜测 08:00 等时刻：必须先节次映射或手填。
- 确认前识别与草稿展示均不写数据库；批量导入仍每批仅发一次兼容的 course.created。
