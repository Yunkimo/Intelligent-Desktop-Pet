## 3. 尚未执行的人工验收（待成员 C 在开发者工具与手机上完成）

1. 首次进入：无需任何配置，业务请求自动微信登录；「设置」页显示登录账号（业务账号 #N）与「退出登录」。
2. 数据隔离：手机小程序（微信账号甲）与另一账号（乙，可通过开发者工具换号或另一台手机）分别建课程/日程/学期，互相看不到；把对方的课程 ID 手工填到请求里应 404（页面删除/编辑他账号资源会提示不存在）。
3. 退出登录：设置页点「退出登录」→ 回列表页下拉刷新 → 业务请求自动重新登录并正常显示本人数据。
4. 同账号跨端一致：桌宠（A19）用配对码登录后，与小程序看到同一账号的课程/日程/学期；桌宠操作后小程序收到本人事件自动刷新。
5. 会话失效：等待会话过期或服务端撤销后，操作只自动重登一次，失败给出明确提示，不无限重试、不转圈。

## 4. 边界与说明

- 小程序侧不再依赖 API Key：`config.example.js` 已注明 apiKey 仅在 B8 过渡期（ALLOW_LEGACY_API_KEY）映射默认演示用户，可留空；业务请求/上传/WS 全部走会话。
- 微信登录返回的 openid 不是凭据；客户端仅保存 session_token（含过期时间），退出即清除。
- 账号切换/退出推进会话代数：旧账号迟到响应被丢弃；学期缓存按账号后缀隔离并在退出时清理。
- B8 不自动认领历史共享数据：升级后小程序首次登录看到的是本人账号的空数据（旧数据归默认演示用户），属预期行为；共享历史迁移不在 C9 范围。
- 同一后端账号在桌宠和小程序读取一致由 B8/A19 保证，C9 仅按契约接入；配对码、设备会话等桌宠侧功能不在本项。
