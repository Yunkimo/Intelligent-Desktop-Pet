## 1. 先检查，不要重复安装

登录你自己的服务器终端，执行：

```bash
date -Is
getent ahostsv4 shynb.beer
curl --fail --max-time 10 https://shynb.beer/api/health
sudo systemctl show idp-backend -p ActiveState -p SubState -p MainPID -p WorkingDirectory -p EnvironmentFiles -p FragmentPath
sudo ss -lntp '( sport = :80 or sport = :443 or sport = :8001 or sport = :8080 )'
```

预期根域名 A 记录为 `8.148.29.9`，HTTPS 返回 `{"status":"ok"}`，后端只监听回环 8001。服务名可能不同；若 idp-backend 不存在，先核实已有部署，不能据此直接另起一个后端。只贴上述必要输出，不贴 .env、系统完整环境、含 token 的 URL 或私钥。

此前探测误用了 8.148.31.9，旧记录不代表实际服务器状态。23:49（北京时间）对正确 IP 定向访问 shynb.beer：HTTP 80 返回备案拦截页 403，HTTPS 443 在严格证书校验下返回 200/status:ok；电脑 DNS 和 dns19.hichina.com 权威查询均未返回根域名 A 记录，见[当前域名检查](evidence/c4/corrected-domain-probe.json)。定向解析成功不能替代正常 DNS、ICP备案或微信真机验收。

DNS 不符时在域名控制台核对 `@` 的 A 记录；如果实际只配置了 `www`，根域名不会自动等效。服务器上可使用下列命令保留域名和 TLS 校验并直接指定 IP，以区分 DNS 和服务问题：

```bash
curl --fail --max-time 10 --resolve shynb.beer:443:8.148.29.9 https://shynb.beer/api/health
curl --fail --max-time 5 http://127.0.0.1:8001/api/health
sudo nginx -t
```

检查安全组/防火墙的 80/443、Nginx 的监听与域名、证书 SAN/有效期/完整链。证书不符时修复证书或选择证书真正覆盖的域名并统一配置，不使用 -k 作为验收。
