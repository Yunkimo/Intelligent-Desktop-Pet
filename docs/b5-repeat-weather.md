# B5 补充：每周提醒与次日带伞提示

对应 Issue #33 中 Yunkimo 的两条补充需求。成员 B 交付后端；桌宠工具接入及小程序横幅由 A/C 使用本契约完成。后端不依赖桌宠在线。

## 每周提醒

```json
{"title":"每周日跑步","remind_at":"2030-01-06T19:00:00+08:00","channel":"pc","repeat_rule":"weekly"}
```

- POST/PUT `/api/reminders` 新增可空 `repeat_rule`，仅支持 `weekly`；非法规则 422。GET 列表及详情原样返回。空值或缺省创建仍是一次性提醒，旧数据行为不变。
- 首个 `remind_at` 决定周几和时间；每周期固定顺延 7×24 小时，存 UTC。适合中国固定时区，不实现夏令时墙钟、RRULE 或节假日跳过。B 端不替用户猜首个周几，A 已有工具计算最近一次时间后可传本字段。
- 重复提醒是独立提醒，不能关联 task_id（422）。日程完成/取消语义继续沿用原 B5，不隐式改为重复日程。
- 重复提醒 `done=false` 表示整个系列启用。一次发送成功后不停止系列，自动生成下一次事件；每次 event_id 不同，同一次重试沿用原 event_id。事件发生记录归档到 `reminder_occurrences`，领取、结果与下一次排期在同一 SQLite 事务内。
- PC 发送成功或有限重试耗尽后顺延。客户端未连接仍按 B2 重试，失败不会冒充发送成功。both 如已登记本次微信授权，等待其终态才顺延，不会因 PC 成功丢弃尚待发送的已授权手机消息；没有手机授权则不自动向微信发送。
- phone 每次需要针对当前 event_id 主动授权。上周期授权不复制到下周期；没有授权时不发送。周期到期超过整周会跳过旧周期。
- 当前周期不超过一周的迟到事件仍沿用 B2 发送/重试；落后整周或更多时不逐次补发，直接排到未来最近一期。调度默认 30 秒，测试可改 1 秒；仍单 worker/单调度实例。
- 整体停止：DELETE，或 PUT `{"done":true}`，或 PUT `{"repeat_rule":null}`。后两者保留记录并取消当前计划，不再发送；清空规则不会留下隐形的一次性提醒。要恢复，明确提交新 remind_at、weekly、done=false。已经出站的请求无法撤回。
- 保留 B8 用户归属与越权 404。重复字段不接受客户端改变归属。

## 次日带伞提示

认证用户调用 `GET /api/weather/tomorrow?city=北京`，不需要桌宠在线或微信订阅授权：

```json
{"status":"ok","city":"北京","date":"2030-01-02","rain":true,"desc":"小雨","tip":"明天有小雨，记得带伞","provider":"wttr.in","source_url":"https://wttr.in/北京","fetched_at":"2030-01-01T21:00:00+08:00"}
```

- 复用 B4 的受限 HTTP 客户端、固定天气来源、输入检查、超时与解压大小限制。选取预报日期与次日一致的逐时天气代码，雨、雪、雷暴均作为带伞天气；不以实况天气代替预报。
- 「明天」按 Asia/Shanghai 计算。无降水返回 rain=false、tip=""；上游失败/缺失目标日期/未知天气代码返回 status=unknown、rain=null、tip=""。unknown 不等于晴，不生成带伞记录。
- 城市/目标日期唯一：当日成功结果缓存，雨天提示表同城同日只保存一条，无雨不生成提示。并发请求共用一次成功获取；失败内存退避 60 秒后可重试，不影响其它业务接口。近期数据保留 7 天。天气为公开城市级数据，不含私人城市偏好；大小写归一，不做城市别名合并。
- 此期选用**配置演示城市**，尚不新增用户城市偏好接口。`WEATHER_TIP_CITY=北京` 可修改。默认 `WEATHER_TIP_ENABLED=false`，生产按需显式启用；启用后每天上海时间 21:00 起独立后台任务预取次日数据（每分钟检查，失败退避，成功当日复用）。当天较早的查询结果也会复用，不强制 21 点再请求一次。
- C 的今日页读取本接口后根据 rain===true 显示 tip；unknown 可显示「暂时无法获取天气」。前端横幅代码由 C 独立接入，不能把后端测试记为界面验收通过。
- 自动微信推送是本评论的可选增强，本次不实现未经逐次授权的自动推送。主路径是可查询横幅，不承诺「每天自动推送」。

## 迁移与复验

- 版本四增量迁移，旧数据 repeat_rule=null，旧事件 ID 不变；迁移前使用 SQLite 快照创建唯一 `.pre-b5-repeat-*.db`，不覆盖既有备份，迁移失败回滚。升级前先停服并保留原库备份；应用启动自动检查版本，重启不重复改写。
- 不改变 B8 的用户迁移规则。回滚先在副本恢复数据库、配套旧代码验证，不自动覆盖线上库。

```bash
python -m pytest backend/tests -q
python -m pytest backend/tests/test_repeat_weather.py -q
```

测试通过注入时钟跨越两周，不必等真实两周；发送和天气分别使用受控替身。自动测试不代替真实模型/天气公网测试或小程序界面人工验收。生产服务器本次未更新。
