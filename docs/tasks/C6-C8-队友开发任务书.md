## 2. 职责与开发规范

- C 负责 `miniprogram/` 的页面、请求/事件适配、客户端测试和操作文档。B 负责数据库、学期计算、模型解析、事务、调度及服务端鉴权；发现后端缺口应提供请求、预期和实际结果，与 B 协作修复。
- 开工先检查工作区和分支，保留其他人的未提交修改。新建独立分支或 worktree；不覆盖用户配置，不重置、清理或强推公共分支。
- 不复制另一台电脑的绝对路径、虚拟环境、数据库或测试 token。使用自己的环境；通过 `config.example.js` 准备被忽略的本机配置，真实凭据不提交、不截图、不打印。
- 沿用原生微信小程序和现有项目风格，避免新增框架、重复连接管理器、重复状态库或模型直连。模型 Key 只留在后端。
- HTTP、上传集中在 `utils/api.js`；配置集中在现有配置入口；WS 由 `utils/ws.js` 管理，页面订阅/退订，不自行建 socket。时间转换复用 `utils/datetime.js`。
- 所有异步操作覆盖成功、失败、取消、超时和退出；释放 loading/按钮锁，保留用户输入。用请求序号或等效机制丢弃迟到结果，旧请求不能覆盖新状态。
- 请求超时不等于服务器未写入。对可能已提交的操作先核对结果；没有可靠幂等依据时不得自动重放创建或整个批次。仅比较同名课程不能保证去重，无法确认时显示“结果待确认”。
- 页面只呈现用户能理解的状态，如“正在识别”“请确认提醒时间”；内部 event_id、模型响应和技术错误细节留在测试/脱敏诊断中。

## 3. C6：自动周数与今日课表

### 必须完成

1. 提供简洁学期设置：第一周的周一、总周数，保存后端；默认时区 Asia/Shanghai。首次未设置时引导配置，不沿用固定第 6/7 周，不根据旧 `current_week` 反推开学日期。
2. 今日页取真实当前日期、星期、周次和当天有效课程；课表页使用同一套学期依据，正确筛选单双周和离散周。启动、回前台、跨午夜、学期配置变化及重连后校准。
3. 将“当前真实周”与“浏览第几周”分开。保留浏览其他周和“回到本周”；浏览不调用 PUT 修改学期，重新进入默认回本周。B6 日历接口返回某一天的课程；周视图需使用周内日期或课程列表筛选，不能把单日结果当整周。
4. 未配置、开学前、学期结束和无课日分别展示；学期外不强行显示第 1/最后一周。离线可复用已确认的学期配置按当地日历日期计算，并提示离线，恢复后校准；注意时区和跨日，不用毫秒差粗略推算夏令时地区的天数。
5. 扩展 WS 事件白名单和页面刷新：`semester.updated`、`course.updated/deleted`、`task.updated/deleted`；沿用原创建和到期事件。按受影响资源合并刷新，删除后读列表，避免请求已删除详情；重连读取 REST 快照。

### B6 已有接口（以目标版本契约再次核对）

沿用当前受控演示鉴权 `X-API-Key`，不要在业务中硬编码。B8/C9 落地后统一切换其会话契约。

| 请求 | 用途 |
|---|---|
| `GET /api/semester` | 获取 `{configured, settings}`；未配置 settings=null |
| `PUT /api/semester` | 整体保存，不是 PATCH |
| `GET /api/calendar` | 按配置时区查询服务器今天 |
| `GET /api/calendar?date=2026-10-30` | 查询指定日期，适合日期浏览和固定样例测试 |

设置请求：

```json
{"start_date":"2026-09-07","total_weeks":18,"timezone":"Asia/Shanghai"}
```

start_date 必须为周一；total_weeks 为 1～53 整数；未知字段、非法时区或日期返回 422。保存请求不要带只读 id。省略 timezone 时默认 Asia/Shanghai。

日历响应包含 `date`、`day_of_week`（周一=1）、`week`、`status`、`timezone`、`settings`、`courses`。
status 为 `unconfigured/before_term/in_term/after_term`；只有 in_term 有真实 week，其余 week=null、courses=[]。
课程 `weeks` 沿用 JSON 字符串表达，空列表表示每周；复用原有解析函数。

WS 沿用 version=1、event_id、type、occurred_at、data.id。`semester.updated` 的 data.id=1。
批量课程导入只发一次兼容的 `course.created`，id 为第一条课程；必须重新取列表，不能认为只新增了一门。
后端不提供历史事件补发或全局顺序。完整契约在 PR #86 的 `docs/b6-contract.md` 和 `docs/api-contract.md`。

### C6 验收

- 第一周设为 2026-09-07：10-25 是第 7 周、10-26 是第 8 周、10-30 是第 8 周周五、10-31 是第 8 周周六。日期是固定样例，不能写成所有用户的默认学期。
- 查询今天不固定传上述日期；跨周或重新进入无需手调。周视图切换不影响今日真实周。
- 指定周、单双周、空 weeks、学期外、无课、未配置、离线、跨端更改都覆盖；错误设置不覆盖原配置。
- 自动化、真实后端、开发者工具和手机分别留证；后端结果正确不能代替页面观察。

## 4. C7：课表图片导入体验优化

### 必须完成

1. 复用当前“识”入口。上传前预览并适度压缩，避免文字被压糊；展示真实阶段和已等待时间，不伪造百分比。若当前上传请求不能区分阶段，先调整适配层或使用准确的合并文案。
2. 与 B7 对齐默认服务端总预算 60 秒、客户端等待上限 70 秒。这个预算是待实现的协作要求，不能只把客户端 180 秒改成更大值当作优化。
3. 提供取消、超时后手动重试。保存 UploadTask/RequestTask 以便 abort；退出或取消后忽略迟到响应，所有分支释放 loading；禁止重复点击。客户端取消不宣称上游计算和费用已撤销。
4. 展示可编辑草稿、跳过/不确定项和警告；核对课程名、星期、地点、教师、周范围、单双周和离散周次。图中没有具体时间时，引导配置节次时间再映射，不能让模型猜 08:00 等时刻。
5. 用户确认后才落库。保存按实际后端返回区分成功、无效、明确失败和结果不明；保留已成功项，只恢复失败项，不能无依据整批重传。完成后刷新课表，保留真实当前周。

### 接口衔接与验收

现有路径是 `POST /api/courses/parse-image` 和 `POST /api/courses/bulk`。B7 的草稿、警告、缺时间字段及错误结构必须核对新契约；现有 bulk 返回 created/skipped，不等于已经有逐条幂等恢复能力。

- 使用同一复杂课表及清晰/模糊样例，记录图片规格、模型、耗时、成功数和准确性；由 B7 提供后端优化前后数据，C 提供用户实际等待记录。
- 超时、取消、退出重进、断网、连点均不永久转圈；旧结果不覆盖新图片结果。
- 确认前数据库不变；核对全部可见课程的周次和时间。部分失败恢复不重复导入，缺时间需确认，不静默套用时刻。
- 测试图片作为 fixture 保存或记录稳定来源；不要假设队友拥有聊天里的图片、本机临时路径或私人课表。

## 5. C8：一句话创建日程与提醒确认

### 必须完成

1. 日程新增入口优先提供文本输入，例如“明天下午三点提醒我交实验报告”；原手动表单保留为修改和失败回退。
2. 调用 B7 文本解析接口，返回一个或多个草稿后展示简洁确认卡，可修改标题、备注、截止日期、提醒时间。接口路径和字段以 B7 确认契约为准，本文不虚构尚未提供的端点。
3. 相对日期按传入的参考日期/时间及明确时区解释。缺失、歧义、过去时间标记待确认；多事项可选择保存。只说截止日期时不自动添加提醒；未确认不保存，不触发微信授权。
4. 保存仅调用 tasks；复用 B5 自动安排 PC 提醒，不额外 POST PC reminder。防连点，保留多条操作的逐项结果；响应不明先核对，不因网络错误新建第二份日程。
5. 接入提醒状态：桌面提醒已安排、微信未授权/需重新授权、完成/取消等以当前服务端记录为准。复用 C3 登录、授权和恢复；内容或时间变化后重新读取当前事件，不能只看旧缓存。
6. 保存失败保留原文和草稿；改期、清空提醒、完成、重开、删除后正确刷新。已经出站的消息不能保证撤回，提示符合真实状态。

### C8 验收

- 固定参考日期 2026-10-30：“明天下午三点提醒我交实验报告”得到 10-31 15:00 提醒草稿；“下周五前交报告”按 B7 契约确认截止语义，不擅自增加提醒。
- 覆盖多事项、无日期、歧义、过去时间、解析失败、取消、修改确认和重复提交；草稿不自动执行。
- 保存后从真实后端读回；带提醒日程只有一条 PC 关联。改期/完成/重开及微信状态符合 B5/C3。
- 用户同意、服务端登记、平台受理、手机实收分别记录；Mock 不代表真实微信发送通过。
