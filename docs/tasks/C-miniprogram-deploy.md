## 1. 项目背景（agent 必读）

「智能桌宠」是期末课设项目，三端架构：

```
桌宠端（成员 A）  ↔  后端（成员 B）  ↔  小程序（你负责）
   PyQt6 + agent      FastAPI + SQLite      微信小程序
   HTTP REST + WebSocket                    HTTP REST + WebSocket
                                    后端 → 微信订阅消息（离线推送）
```

- **后端是唯一数据源**：课表、日程、提醒都存后端 SQLite，三端读写同一份数据。
- 你的端是「移动端 + 交付」：小程序让用户在手机上查改课表/日程、实时刷新、离机收订阅消息；同时负责部署与文档交付。

### C3. 订阅消息授权

对应 [Issue #11](https://github.com/Yunkimo/Intelligent-Desktop-Pet/issues/11)。

#### 背景

用户在小程序中主动订阅提醒后，即使退出小程序，仍希望通过微信收到到期通知。C3 负责授权入口、登录与接口接入、状态反馈及真机验证；微信身份交换、订阅记录和服务端发送由 B3 负责。

#### 范围

- **账号与模板准备**：与 B 核对小程序 AppID、实际可用模板、模板字段及跳转页面。模板 ID 集中配置；账号资格、基础库兼容性及订阅限制按实施时的微信官方文档和账号实际能力核验。
- **登录与身份绑定**：通过 `wx.login` 获取临时 code，对接 `POST /api/wechat/login`；与 B 明确登录返回值、会话携带方式、失效处理和错误格式。服务端依据已验证会话绑定用户，不把客户端提交的 openid 当作身份证明；AppSecret、session_key 和服务端 access_token 不进入小程序。
- **授权入口**：在今日页或日程页提供“订阅提醒”按钮，说明用途和一次性订阅性质。登录及配置准备好后，由用户主动点击触发 `wx.requestSubscribeMessage`；避免页面加载时自动弹窗，并防止重复点击。
- **结果上报与状态反馈**：按模板分别处理同意、拒绝、不可用及调用失败，向 `POST /api/wechat/subscribe` 上报约定字段。区分“用户同意”“后端记录成功”“消息已发送”；不能只凭回调成功或本地标记显示永久订阅成功。
- **异常与重试**：覆盖登录失败/会话过期、网络断开、模板未配置、用户拒绝、授权后上报失败及后端不可用。给出可恢复提示，拒绝授权不影响查改课表/日程；重试上报与 B 对齐幂等语义，不重复累计授权记录或自动重复弹窗。
- **联合验收与交付**：与 B3 核对提醒归属、手机发送状态和消息跳转路径；点击消息后读取后端最新内容，资源删除时友好提示。补充相关客户端测试、接口说明及人工验收记录；估算和共同贡献沿用已有约定，缺失时由 B/C 确认。

#### 验收

1. **正常链路**：真机完成登录 → 主动订阅 → 后端记录 → 创建一条归属当前用户的手机提醒 → 退出小程序 → 到期后微信实际收到消息。保存脱敏截图、提醒标识、计划时间、实际接收时间和服务端结果；记录微信版本、基础库及测试代码 SHA。
2. **身份与授权**：会话失效有明确提示并可重新登录；伪造身份不能订阅或获取他人提醒。用户拒绝、模板不可用、登录失败时不显示订阅成功，基础业务仍可使用。
3. **网络与重复操作**：授权后断网或服务端记录失败能明确显示“未完成/需重试”；恢复后可按约定重试，连续点击或重复上报不产生重复业务记录。
4. **一次性订阅与跳转**：不把一次同意显示为长期有效；无可用发送资格时如实提示，后续订阅由用户主动触发。消息点击后进入约定页面，已删除资源有明确反馈。
5. **完成判定**：相关测试通过、B/C 契约评审完成，保留开发者工具测试与真机实收的独立结果。Mock 成功或微信接口受理不能替代真机收到消息；受账号/模板限制时记录阻塞，不标为通过。

[#7](https://github.com/Yunkimo/Intelligent-Desktop-Pet/issues/7)（B3 登录、会话、订阅记录及发送接口）为核心依赖；[#9](https://github.com/Yunkimo/Intelligent-Desktop-Pet/issues/9)（C1 页面及请求封装）提供基础。公网真机联调依赖 [#12](https://github.com/Yunkimo/Intelligent-Desktop-Pet/issues/12)（C4）的可达地址和域名配置；页面与 Mock 测试可先推进，B/C 接口对齐后再接真实服务。

- 补配置失败、跨周/学期外和旧设置兼容的页面/联调测试及用户说明；不自行实现第二套课程提醒计划。

C6/C7/C8 均为 v1.0.0 后续迭代，按 B5→B6→B7 的契约分阶段接入；每项 B/C 交付分别记录，避免重复计分。
详细范围与验收见 [B/C 分工核对](BC-followup-scope.md)。已存在能力只是依赖，成员评审与新功能实际验收不能由旧结果替代。

## 5. 技术约定（必须遵守）

- 小程序 REST、上传和 WebSocket 地址统一从 `miniprogram/config.js` 的 `baseUrl` 配置派生，分别由 `utils/api.js`、`utils/ws.js` 使用；部署时同时核对 HTTPS/WSS 和相应合法域名。
- 演示采用一次性订阅；用户同意、后端记录、平台受理及真机收到消息分别记录，不承诺“点一次必定收一条”。后续订阅由用户主动触发，实际可用性按微信平台结果核验。
- 微信登录与订阅通过 B3 约定会话绑定身份；openid 不是认证凭据。AppSecret、session_key 和服务端 access_token 不进入小程序。
- 共享 API Key 仅用于现有受控演示，按现有契约走请求头；客户端配置不构成秘密存储或多用户授权。真实配置不提交，公开部署的会话与访问边界由 B/C 评审后实施。
- 服务器运行单 worker、单调度实例并关闭热重载；开发工具的域名校验豁免与正式部署验收分别记录。
